

訊息鑑別碼 (MAC)、密碼雜湊函數 (Hash) 和數位簽章 (Digital Signature) 是==密碼學中用於確保資訊安全的三大核心技術，它們最主要的區別在於能否提供身分鑑別 (Authentication) 以及不可否認性 (Non-repudiation)==。

這三者在功能、密鑰類型以及應用場景上的直接對比：

| 特性                    | 密碼雜湊函數 (Hash)            | 訊息鑑別碼 (MAC / HMAC)          | 數位簽章 (Digital Signature) |
| --------------------- | ------------------------ | --------------------------- | ------------------------ |
| 密鑰類型                  | ❌ 無密鑰                    | 🔑 對稱密鑰（雙方共享同一把私鑰）          | 雙鑰（非對稱密鑰：私鑰簽章、公鑰驗證）      |
| 資料完整性  <br>_(確保沒被竄改)_ | ✅ 可以（但無法防範中間人同時竄改資料與雜湊值） | ✅ 可以（只有擁有密鑰者才能生成正確的 MAC）    | ✅ 可以（任何資料變動都會導致簽章驗證失敗）   |
| 來源鑑別  <br>_(確定是誰發的)_  | ❌ 無法提供                   | ✅ 可以（保證由知道共享密鑰的某一方所發出）      | ✅ 可以（明確對應到唯一擁有該私鑰的特定實體）  |
| 不可否認性  <br>_(事後無法賴帳)_ | ❌ 無法提供                   | ❌ 無法提供（因為雙方都有同把密鑰，無法證明是誰做的） | ✅ 可以（只有私鑰持有者能簽章，具法律效力）   |
| 運算速度                  | ⚡ 極快                     | ⚡ 快                         | 🐌 慢（非對稱加密演算法複雜度較高）      |
| 常見演算法                 | SHA-256, SHA-3, MD5      | HMAC-SHA256                 | RSA, ECDSA, Ed25519      |

## 💡 深入核心概念

## 1. 密碼雜湊函數 (Cryptographic Hash Function)

- 原理：將任意長度的資料輸入，轉換成固定長度的「數位指紋」（Digest）。它具有單向性（無法從結果推回原文）和抗碰撞性（不同輸入極難產生相同雜湊）。
- 盲點：如果攻擊者在傳輸過程中同時修改了「訊息」和「雜湊值」，接收方是無法察覺的。因此它只能檢查資料是否出錯，無法驗證資料是誰發的。

## 2. 訊息鑑別碼 (Message Authentication Code / MAC)

- 原理：為了補足雜湊的盲點，MAC 在計算過程中加入了通訊雙方事前講好的「共享密鑰」。最常見的實現方式是 HMAC（基於雜湊的訊息鑑別碼）。
- 優勢：因為攻擊者沒有密鑰，即使改了訊息也無法算出正確的 MAC，同時確保了完整性與身分鑑別。
- 限制：因為 A 和 B 手上拿著一模一樣的密鑰，A 可以說是 B 偽造了訊息，B 也可以說是 A 偽造的。所以在第三方（如法庭）面前，它不具備不可否認性。

## 3. 數位簽章 (Digital Signature)

- 原理：結合了雜湊函數與非對稱加密技術。發送方先用雜湊函數對訊息產生摘要，再用自己的**私鑰（Private Key）對摘要進行加密（這步驟就是簽章）；接收方則使用發送方的公鑰（Public Key）**來解密並驗證。
- 優勢：由於私鑰只有發送方獨有，全世界只有他能產生這個簽章。這賦予了數位簽章最強大的特性——不可否認性。




現代網路安全（如 HTTPS / TLS 握手) 通常**先用非對稱加密安全地共享臨時的對稱密鑰**，再用對稱加密傳輸實際的大量資料。
