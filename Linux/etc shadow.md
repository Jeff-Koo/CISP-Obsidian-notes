## `/etc/shadow`

`/etc/shadow`（阴影密码文件）是 Linux 系统中专门用来**存储用户密码加密 Hash 值及密码有效期策略**的核心安全文件。

权限必须是 `0000` 或 `0600`（所有者通常为 `root` 或 `shadow` 组，严禁任何普通用户具有读权限）。


### 典型记录与 9 个字段详解

```
admin:$6$qx8vN9z1$7mKzLp...:19723:0:90:7:14::
```

从左到右依次为：
#### 1. 用户名（Username）

- **示例**：`admin`
- **含义**：必须与 `/etc/passwd` 中的用户名一一对应。

#### 2. 加密密码 Hash（Encrypted Password）

- **示例**：`$6$qx8vN9z1$7mKzLp...`
- **格式解析**：通常由 `$` 符分割为三部分：`$算法标识$加盐Salt$密文Hash`
    - **算法标识码**：
        - `$1$`：MD5（旧系统，不安全）
        - `$5$`：SHA-256
        - `$6$`：SHA-512（目前主流 Linux 的默认配置）
        - `$y$` 或 `$2a$`：Yescrypt / Blowfish（较新的 Linux 发行版采用）
    - **特例值**：
        - `!!` 或 `*`：账号被**锁定/禁用密码登录**（通常为系统服务账号）。
        - 空白：该账号**没有密码**（极度危险，允许空密码登录）。

#### 3. 上次修改密码的时间（Last Password Change）

- **示例**：`19723`
- **含义**：以 **1970 年 1 月 1 日（Unix 纪元 UTC）** 为第 0 天算起，到上次修改密码那一天的**总天数**

#### 4. 密码不可修改的最短天数（Min Days）

- **示例**：`0`
- **含义**：修改密码后，必须等待多少天才能再次修改。设为 `0` 表示可以随时修改密码。

#### 5. 密码的最长有效天数（Max Days）

- **示例**：`90`
- **含义**：密码的最长生存周期（密码策略）。强制用户每隔多少天必须更换一次密码（CISP 合规加固常用配置）。

#### 6. 密码过期前的警告天数（Warning Days）

- **示例**：`7`
- **含义**：在密码到达最长有效天数前的第 7 天开始，用户登录系统时会收到“密码即将过期，请及时修改”的提示。

#### 7. 密码过期后的宽限天数/禁用期（Inactivity Days）

- **示例**：`14`
- **含义**：密码过期后，系统给用户的“缓冲期”。在 14 天内登录仍被允许修改密码；若超过 14 天仍未修改，该账户将被**完全锁定/失效**。

#### 8. 账号失效/到期时间（Expiration Date）

- **示例**：空（或填写具体天数）
- **含义**：同样以 **1970-01-01 以来的总天数** 计算。无论密码是否过期，到了这一天，**整个账号彻底停用**（常用于临时员工或外包人员账号）。

#### 9. 保留字段（Reserved）

- **示例**：空
- **含义**：供未来扩展使用，目前没有具体用途。

### 总结图解

$$\underbrace{\texttt{admin}}_{\text{1. 用户名}} : \underbrace{\texttt{\$6\$qx8v...}}_{\text{2. 加密密码}} : \underbrace{\texttt{19723}}_{\text{3. 上次修改日}} : \underbrace{\texttt{0}}_{\text{4. 最小修改间隔}} : \underbrace{\texttt{90}}_{\text{5. 最大有效期}} : \underbrace{\texttt{7}}_{\text{6. 告警天数}} : \underbrace{\texttt{14}}_{\text{7. 宽限锁定天数}} : \underbrace{\texttt{}}_{\text{8. 账号失效日}} : \underbrace{\texttt{}}_{\text{9. 保留字段}}$$
