## 1. 權限基礎與 UID 0 (Root)
* **UID 0**：Linux 系統中最高權限的標識（Superuser / Root）。系統並非透過名稱判斷管理員，而是透過 `uid=0`。（→ [[etc passwd]] 第 3 欄）
* **安全風險**：日常操作禁止直接使用 Root 登入，避免誤刪系統或遭受惡意利用。
* **Sudo 機制**：一般使用者透過加入 `sudo`（或 `wheel`）群組，輸入自身密碼後暫時借用 Root 權限執行指令，並留下完整的稽核日誌（Audit Log）。


## 2. 系統帳號 (System Accounts)
* **UID 範圍**：通常為 `1` 至 `999`。
* **用途**：專門給背景服務或行程（Daemon）使用，例如 `www-data`、`mysql`、`nobody`。
* **安全性特徵**：通常被設定為無法互動式登入（Shell 設為 `/sbin/nologin` 或 `/bin/false`），用以落實「權限隔離」。（→ [[etc passwd]] 第 7 欄）


## 3. 檔案與目錄建立遮罩：Umask
* **定義**：User File-Creation Mode Mask，用來控制新建檔案和目錄的預設權限。
* **運作原理**：透過預設最高權限 **減去** Umask 數值，拿走權限。
    * **目錄預設最高**：$777$
    * **檔案預設最高**：$666$（預設不給予執行權限）
* **範例 (`umask 0022`)**：
    * 新建目錄：$777 - 022 = 755$（擁有者可讀寫執行，群組/其他可讀執行）
    * 新建檔案：$666 - 022 = 644$（擁有者可讀寫，群組/其他唯讀）
* **CISP 考點連結**：正確設定 Umask 可以防止敏感設定檔被非授權使用者修改，符合存取控制與防禦縱深原則。


## 4. 進程主動降權與特權移除 (Privilege Dropping)
* **核心觀念**：Linux 進程可以主動移除或降低自己的特權，這是實現 **「最小權限原則」(Principle of Least Privilege)** 的重要實踐。
* **經典應用場景**：
    1. 服務（如 Nginx、Web Server）必須以 Root 身份啟動，以便綁定特權連接埠（Port $< 1024$，如 80、443）。
    2. 完成初始化與埠綁定後，行程透過系統呼叫（如 `setuid()`、`setgid()`）主動將身份切換為低權限系統帳號（如 `www-data`）。
    3. **防禦效果**：即使後續應用程式遭遠端代碼執行（RCE）漏洞攻擊，駭客也無法直接取得 Root 權限，將損害降至最低。
