### CISP 考点及概念辨析

1. **“面向连接”与“无连接”的区别：**
    - **面向连接（TCP）：** 在真正传输数据之前，通信双方必须先建立逻辑信道（如 TCP 三次握手：SYN $\rightarrow$ SYN-ACK $\rightarrow$ ACK），通信结束后需要显式释放连接。
    - **无连接（UDP / IP）：** 发送方**不打招呼**，直接将数据打包并附上目标地址发送出去。

2. **为什么 IP 和 UDP 是不可靠的？**
    - **IP 的不可靠性：** 网络层路由器如果遇到网络拥塞、链路中断，会直接丢弃 IP 数据包，IP 协议本身**不会尝试重新发送**（通常交由 ICMP 报错 或 上层 **TCP 协议处理重传**）。
    - **UDP 的不可靠性：** UDP 只是在 IP 协议之上包装了一层很薄的端口复用/分用以及校验和功能，不提供任何包到达确认、丢包重传或顺序控制机制。（通常交由 上层 **應用層处理重传** 或直接接受丢包，**不做重传**）。

3. **分层协同逻辑（经典陷阱）：**
    - **问题：“既然底层 IP 协议是不可靠的，为什么基于 IP 的 TCP 却能做到可靠？”**
    - **解析：** 这正是网络协议分层设计的精髓。TCP 作为运行在网络层（IP）之上的**传输层协议**，通过在自己的报文头中引入序号（Sequence Number）、确认号（Acknowledge Number）、定时器和重传逻辑，**在不可靠的 IP 网络信道之上，构建出了可靠的端到端数据传输服务**。

### 解析与 IPsec 理论对比

#### 1. 为什么 D 选项错误（符合题意）？

IPsec 提供的核心安全服务包含三大项：
1. **保密性（Confidentiality）**：通过 ESP 算法加密数据。
2. **可认证性/数据源鉴别（Authentication）**：验证数据来源是否合法。
3. **完整性（Integrity）与防重放（Anti-Replay）**：防止数据在传输过程中被篡改，并利用序列号机制阻断重放攻击（Replay Attacks）。


IPsec 的两大核心协议 **AH（认证头协议）** 和 **ESP（封装安全载荷协议）**，均可以与 **传输模式（Transport Mode）** 和 **隧道模式（Tunnel Mode）** 自由组合搭配使用。


### IPsec 模式对比速记表

| **维度**     | **传输模式 (Transport Mode)** | **隧道模式 (Tunnel Mode)**                      |
| ---------- | ------------------------- | ------------------------------------------- |
| **保护范围**   | 仅保护 **IP Payload**        | 保护 **整个原始 IP 数据包（IP Header + Payload）**     |
| **IP 头处理** | 保留原 IP 头                  | 隐藏原 IP 头，叠加 **新 IP 头（New IP Header）**       |
| **典型场景**   | 主机到主机（Host-to-Host）直接加密通信 | 站点到站点（Site-to-Site / Gateway-to-Gateway）VPN |
